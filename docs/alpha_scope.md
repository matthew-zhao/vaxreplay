# VaxReplay technical-preview scope

VaxReplay is currently a pre-alpha research toolkit, not a validated vaccine-development
benchmark. This document is the controlling public claim for the planned
`v0.1.0-alpha.1` technical preview.

## What the preview may claim

The preview may describe:

- schemas and deterministic scoring contracts for temporally controlled evaluations;
- historical-source adapter interfaces;
- contamination-control and one-attempt protocol designs;
- development-only sealed-runner and provider-gateway components;
- unit-tested reference implementations; and
- wholly fictional conformance fixtures.

An implementation or test may be described as `development-only`, `synthetic`, `fictional`,
`proposed`, or `unit-tested` when that description is accurate. A local deterministic or nested-KVM
drill is development evidence only. It is not independent qualification, production attestation, or
an official benchmark run.

## What the preview does not contain

The public technical preview must not contain:

- the 131 real AACT development workspaces;
- real task identities selected for evaluation;
- private gold, organizer mappings, exact cohort inventories, or scorer secrets;
- raw IEDB, AACT/ClinicalTrials.gov, ImmPort, VaxSeer, or FluSelect source slices;
- customer or model submissions, raw provider responses, or private run logs;
- provider credentials, HMAC keys, databases, ledgers, VM disks, kernels, or root filesystems;
- an admitted Tier A or Tier B benchmark cohort; or
- a scientifically valid model leaderboard.

The current AACT development cohort forecasts registry-observed trial execution. It does not
measure biological efficacy, immune response, safety, clinical utility, candidate quality, or
end-to-end vaccine-development capability.

## Release boundary

The technical preview will be produced as a fresh allowlisted export, not by copying the development
working tree and not by publishing its Git history. The export must be built from a reviewed, clean
source revision and independently inspected before release.

Only project code, approved documentation, ordinary examples, unit tests, and explicitly fictional
fixtures may enter the export. Generated `build/` artifacts, ignored `private/` material, organizer
state, real cohort data, branded model-result receipts, and raw development evidence are denied by
default.

The release archive must pass:

1. an exact path allowlist;
2. secret and private-identifier scanning;
3. lint, format, type, unit-test, package-build, and clean-install checks;
4. source, wheel, and sdist inventory review;
5. dependency and license review;
6. checksum and software-bill-of-materials generation; and
7. confirmation of code ownership, data terms, security contact, and citation identity.

## Intended use

The preview is intended for evaluation research, protocol review, and development of compatible
model or agent harnesses. It is not medical software, clinical decision support, a regulatory
artifact, or evidence that a model can safely develop a vaccine.

## Commercial boundary

Real held-out tasks, private gold, identity mappings, and managed execution remain outside the
public preview. A future paid design-partner pilot may evaluate customer-approved systems in a
private environment under a separately frozen protocol, rights review, retention policy, and
publication agreement.

Results apply only to the exact cohort, model route, harness, resource budget, and execution policy
that produced them. No score should be generalized to vaccine development without an independently
validated biological task lane.
